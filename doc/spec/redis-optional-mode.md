# Redis 可选开关与本机内存模式

## Context

为本地调试移除 Redis 必选依赖。用户已确认本规格：`REDIS_ENABLED` 默认 `false`，仅接受 `true/false`，重启生效。关闭时仅监听 `127.0.0.1`，不创建 Redis 连接；开启时沿用原有监听方式和 Redis 能力，不自动降级。启动日志显示开关、模式与地址。

## Model

不修改数据库模型。内存 TTL 键值存储承载 token 黑名单与群聊短期上下文；共享的内存运行流承载单聊/群聊事件、归属、互斥与中止。每轮最多保留 5,000 条事件，完成后保留 1 小时，活跃状态安全 TTL 为 2 小时。过期数据定期清理，取消订阅及模块销毁释放等待者与定时器。

## Backend API

REST 路径、请求响应和 SSE 事件格式不变。现有 `TurnStream` / `GroupRunStream` 方法保持不变。单聊订阅使用 `session.id` 作为内部归属键。不开设配置写入接口或前端设置页。

## Runtime Flow

1. 启动时严格解析开关，非法配置立即报错；开启才创建 Redis 客户端。
2. 黑名单与群聊热上下文按配置使用 Redis 或内存 TTL 存储。
3. 内存模式原子占用会话/群活跃状态，保留归属校验，通过缓冲回放与实时追尾提供事件。
4. 释放活跃指针不会提前关闭流，后续 `done` 必须可被消费；中止直接通知本进程处理器。
5. 内存模式启动回收返回零。重启不恢复运行态，已持久化聊天历史继续从 MySQL 读取。

## Validation

测试配置及客户端工厂、TTL、互斥与归属、事件回放接追尾、快速完成、中止、取消、过期与销毁；验证 Redis 分支仍使用连接/Stream/控制频道。执行 server 类型检查及相关 node:test 测试。真实 MySQL、Redis、模型/CLI 联调按可用环境执行，并在实现后记录未执行项。

## Known Limits

- 本机单进程模式仍需 MySQL、模型及现有 CLI 依赖，不限制 Agent 执行方式。
- 仅保障单客户端；不保证多端围观，不增加设备识别或订阅排他限制。
- 重启丢失事件缓冲、活跃状态、热上下文和黑名单。已吊销但未过期 JWT 可能再次有效；数据库历史保留。
- 不做状态持久化、运行恢复、数据库迁移或热切换。原有 Redis 部署必须显式设置 `REDIS_ENABLED=true`。
